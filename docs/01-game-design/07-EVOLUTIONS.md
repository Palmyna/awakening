# Project Awakening — Évolutions

**Statut :** Draft de conception — base initiale à compléter

## 1. Rôle et périmètre du document

Ce document rassemble les décisions validées concernant les arbres, les conditions et le déroulement des évolutions de créatures.

Il approfondit le [référentiel Créatures](./03-CREATURES.md) sans le remplacer. Les valeurs propres à chaque famille, les conditions de créatures concrètes et l’interface finale ne sont pas définies ici.

## 2. Structure d’un parcours d’évolution

Une famille peut contenir de nombreuses formes, branches et sous-branches.

Chaque instance parcourt cependant exactement trois stades :

1. stade 1 — forme de base ;
2. stade 2 — forme intermédiaire ;
3. stade 3 — forme finale.

Une divergence peut commencer au stade 2 ou au stade 3. Une famille linéaire ne possède qu’un chemin ; une famille ramifiée en possède plusieurs.

L’évolution transforme la même instance. Elle ne crée pas une nouvelle créature et ne remplace pas son identité individuelle.

## 3. Effets d’une évolution

Une évolution peut modifier :

* l’apparence ;
* le ou les éléments ;
* le profil de caractéristiques de base ;
* les rôles suggérés ;
* le profil offensif ;
* les versions de la Basic Attack et des Skills.

Le multiplicateur de stade appliqué aux caractéristiques principales et secondaires de base de la forme actuelle est :

* stade 1 : ×1 ;
* stade 2 : ×2 ;
* stade 3 : ×3.

La Basic Attack et les quatre Skills conservent leur continuité conceptuelle, et la catégorie de chaque Skill reste inchangée. Une évolution peut enrichir leur version ou transformer fortement leur fonction lorsque cette transformation reste cohérente avec l’évolution de la créature. Une capacité ne doit pas être remplacée arbitrairement par une capacité sans relation conceptuelle.

## 4. Conditions d’évolution

Chaque transition possède ses propres conditions. Elles peuvent notamment dépendre :

* d’un niveau minimum ;
* d’un niveau d’étoiles minimum ;
* de la possession ou du port d’un objet ;
* d’une autre condition explicitement définie pour cette évolution.

Une condition de niveau est toujours un minimum, jamais un niveau exact.

Un objet simplement possédé, porté ou équipé pour satisfaire une condition n’est pas consommé. Une consommation doit être explicitement déclarée par l’évolution concernée.

Le système ne doit pas imposer un modèle uniforme de conditions à toutes les familles.

## 5. Découverte et connaissance du compte

Les conditions peuvent être inconnues avant leur première découverte.

Le jeu doit fournir des indices cohérents par le lore, les descriptions d’objets, les activités, les ennemis ou d’autres éléments du monde. Une condition ne doit pas reposer sur une association totalement arbitraire exigeant une ressource externe.

Une condition découverte devient une connaissance permanente du compte.

L’encyclopédie révèle progressivement les formes et branches obtenues. Une famille nouvellement découverte peut être présentée comme :

> Forme de base → ??? → ???

Le nombre de branches possibles reste caché tant qu’elles ne sont pas découvertes.

## 6. Déclenchement

Une évolution se déclenche lors d’une montée de niveau lorsque toutes ses conditions sont remplies.

L’XP est attribuée après le combat, puis le nouveau niveau est établi. Si une récompense accorde plusieurs niveaux et permet plusieurs évolutions successives, celles-ci peuvent toutes se produire et sont présentées l’une après l’autre.

Une instance ayant dépassé le niveau minimum sans remplir une autre condition pourra évoluer lors d’une montée de niveau ultérieure, dès que toutes les conditions seront réunies.

## 7. Branches concurrentes

Les conditions de branches concurrentes doivent idéalement permettre au joueur de provoquer volontairement la branche recherchée.

Elles peuvent être mutuellement exclusives. Si plusieurs branches restent valides simultanément, le joueur choisit exceptionnellement celle à appliquer.

Le choix d’une branche est définitif pour l’instance. Une autre branche nécessite le développement d’une autre instance de la même famille.

## 8. Conservation de la progression

Une évolution conserve notamment :

* le niveau et l’XP ;
* les étoiles ;
* les points attribués et non attribués ;
* l’ensemble d’équipement ;
* le surnom ;
* les tags ;
* le verrouillage.

Les points déjà attribués restent dans les caractéristiques choisies, même lorsque la nouvelle forme possède un profil intrinsèque différent.

## 9. Apparences de formes

Chaque forme atteinte débloque définitivement son apparence pour l’instance concernée.

Une instance peut afficher une ancienne forme réellement parcourue sur son propre chemin, sans acquérir l’apparence d’une branche non empruntée. Ce choix reste cosmétique et ne modifie jamais sa forme mécanique actuelle.
